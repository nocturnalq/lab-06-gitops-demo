- Отчет должен быть уникальным: кластер kind и пространство имен сервиса называются вашим ником (см. «Как запустить»), поэтому на всех скриншотах и в выводах команд видны имена узлов `<ник_k8s>-control-plane`, `<ник_k8s>-worker` и пространство имен `<ник_k8s>`.

- Отчеты, совпадающие по содержанию с чужими, не засчитываются.

## Задание

Компания уходит с self-hosted Gitea на GitHub, и сервис `notes` переезжает первым.
Заодно решили навести порядок с деплоем: в лабе 3 его делал конвейер, в лабах 4 и 5 - вы руками через `kubectl apply` и `helm install`, и теперь никто не может сказать, что на самом деле крутится в кластере и кто это выкатил.
Новое правило: в кластере работает ровно то, что лежит в ветке `master`, и руками в кластер никто не ходит.

Ваша задача - перенести сервис и его CI на GitHub, поставить в кластер Flux через Flux Operator и отдать ему все: стек мониторинга из лабы 5, сам сервис и выкатку каждого нового образа, собранного из `master`.

## Где взять образ

Код сервиса - ваш репозиторий `dev/notes` из лабораторной 3: контейнер `lab-01-pipeline-task-1` должен быть запущен (порт 3000 опубликован на `127.0.0.1`), а его тома не удалены.
Манифесты `notes` и `gateway` - ваши из лабораторных 4 и 5, values стека мониторинга - `configs/monitoring-values.yaml` из лабораторной 5.
Образы в этой лабораторной собирает только ваш CI в GitHub Actions и публикует в GitHub Container Registry (`ghcr.io`).

## Как запустить

Нужны Docker с не меньше 8 ГБ свободной памяти, [kind](https://kind.sigs.k8s.io/docs/user/quick-start/#installation), [kubectl](https://kubernetes.io/docs/tasks/tools/), [helm](https://helm.sh/docs/intro/install/), git, аккаунт на GitHub и браузер.
Очень пригодится CLI [flux](https://fluxcd.io/flux/installation/#install-the-flux-cli) версии 2.10: `flux get all -A`, `flux reconcile`, `flux events` экономят много времени.
Все команды выполняются из каталога этого задания (`task-1`), конфиги лежат в `configs/`.

Кластер называется вашим ником `<ник_k8s>` (ник в Telegram в нижнем регистре, `_` заменено на `-`), так же называется пространство имен сервиса.
Кластер из лабораторной 5 с тем же именем сначала удалите: `kind delete cluster --name <ник_k8s>`.
Когда закончите, удалите и этот кластер той же командой.

Ниже `<github_user>` - ваш логин на GitHub.

## Проверка решения

Решение принято, если одновременно:

- репозиторий `<github_user>/notes` приватный, основная ветка `master`, в нем код сервиса, workflow GitHub Actions и все манифесты кластера, но нет ни одного токена или пароля;
- workflow на коммит в `master` выполняет `lint`, `build`, `test` и публикует в `ghcr.io/<github_user>/notes` образ для `linux/amd64` и `linux/arm64` с тегом `master-<короткий sha>-<unix time коммита>`, а на Pull-request только проверяет;
- Flux установлен через Flux Operator из одного `FluxInstance`, синхронизирует кластер из `master` и сам ставит стек мониторинга и сервис;
- новый коммит в `master` доходит до `/version` на `localhost:8080` без команд к кластеру, через коммит Flux с новым тегом, который не запускает CI;
- ручные изменения в кластере откатываются Flux;
- все поды в `monitoring`, `flux-system` и `<ник_k8s>` запущены.

Автоматической проверки у задания нет: преподаватель проверяет перечисленные условия по отчету и репозиторию.

## Правила

- Работайте только со своим кластером kind и своим репозиторием.
- После установки `FluxInstance` руками в кластер ставятся только Secret; все остальное попадает в кластер через коммит. Ручные изменения из шагов задания, которые проверяют реакцию Flux, не в счет.
- Код сервиса менять можно, но образы собирает только ваш CI.
- Не публикуйте в отчете и не коммитьте пароли и токены: заменяйте их на `<пароль>`, `<токен>`.
